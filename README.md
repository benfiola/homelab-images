# homelab-images

Container images and Kubernetes controllers built for my personal [homelab](https://benfiola.github.io/homelab/). The code is public in case it's a useful starting point, but it's built for my needs, not as a general-purpose toolkit.

## Components

Each top-level directory with a `Dockerfile` is a component, published as `ghcr.io/benfiola/homelab-images/<component>` (and, where it has a `chart/`, as a Helm chart under `oci://ghcr.io/benfiola/homelab-images/charts`).

| Component                                                  | Description                                                |
| ---------------------------------------------------------- | ---------------------------------------------------------- |
| [bucket-sync](bucket-sync/README.md)                       | Controller for scheduled rclone bucket syncs               |
| [dynamic-dns](dynamic-dns/README.md)                       | Keeps Cloudflare DNS records in sync with a dynamic IP     |
| [home-assistant](home-assistant/README.md)                 | home-assistant with the Frigate integration                |
| [linstor-provision-disk](linstor-provision-disk/README.md) | Init container that resets LINSTOR satellite storage       |
| [lvm2](lvm2/README.md)                                     | lvm2 tooling image                                         |

| [music-assistant](music-assistant/README.md)               | music-assistant with a stream base URL override            |
| [pvc-restore](pvc-restore/README.md)                       | Controller restoring PVCs from volsync backups             |

## Layout

- One Go module at the repo root. `shared/pkg/` holds helpers imported by components.
- Each component lives in its own directory: `Dockerfile`, optional `cmd/` + `internal/` (Go), optional `chart/` (Helm).
- `scripts/` is the release tooling (`go run ./scripts`).

## Development

Everything runs inside the Nix dev shell, which provides Go, Helm, gh and git.

- **Devcontainer** (recommended): reopen the repo in a container. Nix is installed and the dev shell is loaded in every terminal.
- **Local**: install [Nix](https://nixos.org/download) with flakes and run `nix develop`.

Code is formatted with `gofmt` and [Prettier](https://prettier.io/); both run on save in the devcontainer.

Build a component's artifacts locally (they land in `<component>/.build`):

```sh
go run ./scripts build <component> v0.0.0-dev
```

Kubernetes controllers (those with `+kubebuilder` markers) get their deepcopy code, CRDs and RBAC regenerated by `build`. `controller-gen` is built by the dev shell (`flake.nix`); Renovate tracks its version there.

## Releases

Every component is versioned independently with `<component>/v<semver>` git tags. Pushing to `main` releases whatever changed:

1. `go run ./scripts plan` finds each component's unreleased commits. A component is affected by its own directory, the `shared/` packages it actually imports (resolved with `go list -deps`), and `go.mod` changes to modules it imports. Markdown and tests are ignored.
2. The next version comes from those commits' [conventional commit](https://www.conventionalcommits.org) types: `!`/`BREAKING CHANGE` is major, `feat` is minor, anything else is patch. Scopes aren't used.
3. For each affected component, CI builds, pushes the image and chart, and creates the tag and GitHub release.

So a change to `shared/pkg/lvm` releases only the components importing it. Other branches publish prereleases (`-alpha.<run>+<branch>`, or `-rc.<run>` from `dev`). The workflow can also be run manually to release specific components or all of them.

Components build for `linux/amd64` by default. A component that supports more adds a `# platforms: linux/amd64,linux/arm64` line to its Dockerfile, which controls both the Go binaries and the image.

## Dependency updates

[Renovate](https://docs.renovatebot.com) opens PRs for updates, configured in `renovate.json`. Its Dependency Dashboard issue lists pending updates and everything detected. Go modules, `flake.lock`, GitHub Actions, devcontainers and Dockerfile `FROM` lines are tracked automatically. Anything else is tracked with a comment on the line above the version (`//` in Go):

```sh
# renovate: datasource=github-releases depName=helm/helm extractVersion=^v(?<version>.+)$
HELM_VERSION=4.3.1
```

`versioning` and `extractVersion` are optional. For repos without releases, track a commit with `datasource=git-refs depName=<repo url> branch=<branch>` above a 40-character sha.

Hold a version back (shown in the dashboard, never updated) with:

```sh
# renovate-pinned: depName=cuda reason=matches the host GPU driver
CUDA_VERSION="12.4"
```

Rules in `renovate.json` start their `description` with a type: `GROUPING` (land in one PR), `VERSIONS` (allowed versions), `OPT-IN` (PR only when ticked in the dashboard), `PINNED` (backs `renovate-pinned`), `PR NOTE` (reminder added to the PR body).
